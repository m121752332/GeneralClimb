## 背景與範圍

以 Cocos Creator 3.8 + TypeScript 製作垂直攀爬遊戲（最初規劃 2D，2026-11-13 起攀爬關卡改 3D，見 ADR-10），共 14 關，從 1 樓爬到 101 塔尖，核心樂趣是「看懂風險、該停就停」。

靈感來源：國際攀岩好手 Alex Honnold（台灣暱稱「霍將軍」）以無繩索、無安全網的方式挑戰攀爬台北 101（[鏡週刊 2026-01-24 報導](https://www.mirrormedia.mg/story/amp/20260124edi031)）。

**範圍內**：開場、14 關垂直攀爬、關卡間上捲過場、破關環顧城市動畫；風險值系統（太靠邊、強風、下雨、老鷹）；墜落回 1 樓；尖塔段垂直爬梯（背景維持 101 原貌）。

**範圍外（第一版）**：射擊與戰鬥（「魂斗羅風格」只指像素美術、節奏與手感）、多人連線、付費機制。線上排行榜原列第二版，2026-11-14 提前：登頂次數與最快時間排行榜已在第一版（ADR-09 修訂）；樓層排行榜仍是第二版。

## ADR-01 技術選型

**決策**：Cocos Creator 3.8 LTS + TypeScript。第一版輸出 Web Mobile / Web Desktop；Android、iOS 原生打包後期決定。關卡與風險參數放 `levels.json`，程式不寫死數值。

**理由**：同一專案可建置網頁與 Android / iOS；視覺編輯器適合風、雨粒子與光線特效；TypeScript；3.8 為官方 LTS（[Cocos 論壇](https://discuss.cocos2d-x.org/t/cocos-creator-3-8-2-lts-has-been-released/60245)）。

**引擎現況**：2026-01-05 Cocos 宣布 COCOS 4 以 MIT 授權全面開源，引擎與編輯器拆開，編輯器改為獨立 IDE「PinK」；COCOS 4 為 3.x 演進版並承諾向前相容。先用 3.8 LTS，原生打包階段再評估是否升級。

| 方案 | 優點 | 缺點 | 結論 |
| --- | --- | --- | --- |
| Cocos Creator 3.8 LTS | 穩定、編輯器完整、網頁與原生一次涵蓋 | 編輯器進入轉型期 | **採用** |
| COCOS 4 + PinK | MIT 開源、官方未來主線 | 編輯功能仍在遷移 | 觀察 |
| Phaser 3 + TS | 網頁輕量 | 原生 App 要另外包 | 不採用 |
| Godot 4 | 免費、原生輸出強 | 要學 GDScript | 不採用 |

**系統切分**：Scenes：Boot → Home → Intro → Climb → Transition → Fall → Victory；Practice。Components：InputController、RiskSystem、WeatherSystem、EagleSystem、WindowCrowd、LevelLoader、AuthService。事件用種子亂數。

**實作修訂（2026-11-20 記錄）**：實際只建 `Boot`、`Home`、`Climb` 三個 Cocos 場景。開場是 Home 上的疊層（`ui/IntroOverlay.ts`）；Intro（拉近）、Transition、Fall、Victory、Practice 都是 `Climb.ts` 的 mode，共用同一份 3D 世界，避免切場景重建網格。上述 Components 的規則集中在純 TS 的 `climb/ClimbCore.ts`（`EventScheduler`、`ClimbSim`），cc 元件只處理輸入、繪製與流程，方便 `node --test`。

**後果**：場景與 Prefab 為編輯器產生的 JSON，同一場景同時只一人改，邏輯寫在 TS 元件。

## ADR-02 核心操作與攀爬機制

**決策**：101 外牆正面視角，角色沿窗框格線上下左右移動；**放開所有方向鍵 = 靜止抓牢**，是闖過風、雨、老鷹的唯一方法。

**抓牢狀態**：放開方向鍵後角色四肢貼緊牆面、低頭；不另設按鈕。抓牢時不受風、雨影響，也不會被老鷹發現。

| 裝置 | 移動 | 靜止抓牢 |
| --- | --- | --- |
| 鍵盤 | 方向鍵 / WASD | 不按任何鍵 |
| 手機 | 左下虛擬搖桿 | 手指離開搖桿 |
| 手把 | 左類比 / 十字鍵 | 放開 |

- 每格 = 一塊窗格，一次爬一格，16-bit 像素動畫（**已由 ADR-10 取代**：低多邊形 3D、頂點色）
- 水平五區：墜落線｜危險區｜安全區｜危險區｜墜落線（**ADR-10 四面環繞後沒有墜落線**，轉角是兩面危險欄相接的危險區；每側危險欄 1 欄，見 `levels.json` 的 `widths`）
- 101 每節外牆外斜，進入新一節時安全區變窄
- 不提供跳躍、射擊

**關卡上捲**（參考 FC《Ice Climber》，只借用上捲過場）：抵達平台 → 鏡頭約 1.5 秒上捲 → 出現下一關樓層標示，無黑屏 → 繼續爬。不加敲磚、跳躍。

## ADR-03 風險值系統

| 風險值 | 狀態 | 角色表現 | 畫面與音效 |
| --- | --- | --- | --- |
| 0–39 | 安全 | 正常攀爬 | 風聲、城市音 |
| 40–69 | 緊張 | 發抖、冒汗、抱緊牆 | 心跳、邊緣淡紅 |
| 70–99 | 危機 | 單手懸掛、腳滑；操作輕微延遲 | 心跳加快、畫面微晃、紅框閃爍 |
| 100 | 墜落 | 失手後仰往下掉 | 尖叫 → 墜落場景 |

| 來源 | 條件 | 風險變化 |
| --- | --- | --- |
| 危險區 | 在左右邊緣區帶 | 每秒 +15 |
| 墜落線 | 踏出最外側窗格 | 直接 100 |
| 強風中移動 | 強風期間有方向輸入 | 每秒 +25，被向外推 |
| 下雨中移動 | 雨中移動超過 0.3 秒 | 直接 100 |
| 老鷹攻擊 | 被發現後仍移動 | 直接 100 |
| 回穩 | 安全區靜止抓牢 | 每秒 −20 |
| 回穩 | 安全區正常攀爬 | 每秒 −5 |

跨關不重置風險值。

## ADR-04 環境事件

| 事件 | 多久一次 | 預警（前 1 秒） | 持續 | 沒停下來的後果 |
| --- | --- | --- | --- | --- |
| 強風 | 每 60 秒判定，有機率發生（依關卡） | 左上「強風」圖示；雲加速、旗子傾斜 | 隨機 10–20 秒 | 風險每秒 +25，被推向外側 |
| 下雨 | 每 600 秒 | 左上「下雨」圖示；天轉暗、滾雷 | 隨機 20–30 秒 | 雨中移動超過 0.3 秒即墜落 |
| 老鷹 | 第 90 秒起每 120 秒（2026-11-14 試玩修訂，原 300／600） | 左上「老鷹」圖示；鷹嘯 | 固定 3 秒快速飛過 | 移動中被發現 → 俯衝 → 墜落 |

- 計時只算實際攀爬時間；墜落重來歸零
- 圖示事件期間保留並顯示剩餘時間條；三個圖示形狀可區分
- **同一時間只有一個危機事件**：到期事件排隊，前一個結束後至少 4 秒才觸發；強風判定撞到其他事件則跳過
- 老鷹：靜止 = 隱身（貼牆半透明）；移動中被發現有約 1.2 秒警告，停下即轉隱身
- **老鷹修訂（2026-11-14，PR #18、#19）**：改為 3D 展翅老鷹與俯衝。老鷹在場時一移動就被鎖定（紅眼＋紅閃＋尖嘯），`spotSec`（0.6 秒）後朝當下那格俯衝 `diveSec`（0.8 秒），落點 `hitCols` 欄／`hitRows` 列內即墜落，閃遠了就撲空、`diveSec` 後才能再鎖定。**鎖定後停下也來不及**，取代上一行的「停下即轉隱身」；全程不動仍安全。數值在 `levels.json` 的 `events.eagle`。

**環境動畫**：強風（風線、落葉）、老鷹（拍翅飛過、影子掃過玻璃）、烈日（純視覺，亮度與反光）、下雨（雨絲、水珠、閃電）、窗內群眾（NPC 拍照、揮手，純視覺；閃光低頻低亮，可關閉）。

## ADR-06 失敗與重來規則

任何一關墜落即本局結束，一律從 1F 第 1 關重來，無中繼點、無命數。

關卡解鎖（2026-11-14 修訂）：破第 N 關即解鎖第 N+1 關，存在本機（`gcr.progress.v1`），退出或重新整理都保留；選關可從已解鎖的關接著玩；墜落仍回 1F 重來，解鎖同時重置回第 1 關（只有第 1 關開）。看完第 14 關登頂動畫算完成一個周目：解鎖重置回第 1 關、周目數與登頂次數各加 1。練習模式與開發人員模式不記錄。登頂次數之後隨 Google 登入同步到雲端（以 `summits - syncedSummits` 增量累加）。墜落流程：凍結 0.3 秒 → 墜落動畫（不呈現撞擊）→ 結算（最高樓層、墜落原因、歷史最佳）→ 再爬一次。

練習模式：主畫面「開始遊戲」與「練習模式」；練習 = 三層樓平房，風、雨、老鷹各低強度示範一次，約 1 分鐘，不計紀錄。

## ADR-07 開場與破關場景

開場：原創插畫（紅衣角色 + 101 天際線）放大 3 秒 → 主畫面（Google 登入、開始遊戲、練習模式）→ 鏡頭拉近 101 底部 → 第 1 關。
破關（約 15 秒）：觸及塔尖 → 音樂高昂 → 環顧城市 → 360° 台北市景 → 揮手、總時間、墜落次數。

**實作（2026-11-14，PR #16）**：3 秒開場插畫每次開網頁只播一次（`GameSession.introPlayed`），從關卡退回主畫面不再播；按開始遊戲或選關後，Climb 先跑 2 秒鏡頭拉近塔底（不計時，墜落重來不再播）。兩段都可點擊或按任意鍵略過，開頭 0.25 秒內不接受，避免同一下點擊直接跳過。時間與鏡頭數學在純 TS `core/Cutscene.ts`。破關鏡頭由 ADR-10 的 10 秒結束動畫取代（第一次也可略過），結算顯示現實攀爬時間、遊戲時間、種子與周目；墜落次數未顯示（墜落即重開一局，沒有累計意義）。

## ADR-08 素材、肖像與商標風險

素材全面原創；角色無品牌 Logo、臉不仿真人。公開版名稱沿用「霍將軍爬101大樓」，未登入時角色預設名「霍將軍」。
殘留風險：「霍將軍」為真人暱稱，可能被理解為代言或授權；「TAIPEI 101」為註冊商標。上架商店前請法務確認，必要時只換名稱。（設計風險提示，非法律意見）

## ADR-09 Google 登入與玩家名稱

| 狀態 | 角色名稱 | 紀錄 |
| --- | --- | --- |
| 未登入 | 「霍將軍」 | 本機 localStorage |
| 已登入未改名 | Google 顯示名稱 | 雲端 |
| 已登入已改名 | 玩家設定（2–12 字，見下方改名修訂） | 雲端 |

實作：**Firebase Authentication + Firestore（採用）**；自建 Java API 不採用（保留日後串接）。只存 uid、名稱、紀錄，不存 Email；需隱私權聲明。

**部署 GitHub Pages**：
1. Firebase 授權網域加入 `<帳號>.github.io`
2. Google 登入一律 `signInWithPopup`（redirect 在封鎖第三方儲存的瀏覽器會失效，[Firebase 文件](https://firebase.google.com/docs/auth/web/redirect-best-practices?hl=zh-TW)）
3. 彈窗必須由玩家點按鈕觸發
4. Firebase 設定可進公開 repo；服務帳戶金鑰絕不 commit；安全靠 Firestore 規則
5. GitHub Actions 發布 Pages

**第二版排行榜**：沿用 Firestore；登入者每人一筆最佳紀錄，依樓層高→低、時間短→長取前 50（複合索引）；第一層防作弊用安全規則擋不合理數字；伺服器驗證需 Cloud Functions（Blaze 方案）。備選 Supabase（可接 Firebase 登入，[文件](https://supabase.com/docs/guides/auth/third-party/firebase-auth)；免費專案一週低活動會暫停）。

**登頂次數排行榜（2026-11-14 修訂，提前到第一版）**：Firestore `summits/{uid}` = `{ name, count, updatedAt }`，任何人可讀，只能寫自己的。第一次上傳 count 必須是 1；之後每增加 k 次，`request.time` 要比 `updatedAt` 晚 k × `cloud.minSummitSec`（300 秒，`levels.json`）；count 只增不減，只改名時 count 與 updatedAt 不動；可刪自己的（刪除帳號）。本機 `summits - syncedSummits` 依規則允許的量分次上傳，不會遺失也不會重複。排行榜依 count 由高到低取 `cloud.leaderboardSize` 名，同次數先達成者在前。Firebase SDK（compat 版）在 Boot「載入帳號」階段從 gstatic 載入，載入失敗一律以訪客進行。帳號面板：Email（只顯示不儲存）、同步狀態＋立即同步、玩家名稱 `名字#六位數`、登出、刪除帳號、隱私權政策／服務條款（`build-templates/web-mobile/privacy.html`、`terms.html`）。設定步驟見 `docs/firebase-setup.md`。

**改名修訂（2026-11-15，PR #30）**：只能改 `#` 前的名字，`#編號` 由 uid 產生不變。規則在 `core/PlayerName.ts`：去控制／零寬字元、合併空白、去頭尾空白後 2–12 字，只允許中英文、數字、`_`、空白、`-`（不另做不雅字過濾，字元白名單已排除大部分惡意內容；日後要加再另開決策）。`players/{uid}` = `{ name, nameUpdatedAt }`，一個 transaction 同時更新自己的 `summits/{uid}.name`；冷卻 `cloud.renameCooldownSec`（30 秒）與 `firestore.rules` 一致。

**排行榜分頁修訂（2026-11-15，PR #31）**：排行榜分「總周目」（`count` 由高到低）與「最快時間」（`bestRunMs` 由快到慢）兩頁，各取 `cloud.leaderboardSize`（20）名。最快時間只計從第 1 關一次爬到塔尖、不墜落的正式玩法（練習、開發人員模式、從選關接著玩都不算），計時只算攀爬中。`summits/{uid}.bestRunMs` 規則：int、≥ `cloud.minRunSec` × 1000（420000 ms，理論最快約 457.8 秒）、只能變小、有了不能刪。

**資料修訂**：GDD §8 的 `players/{uid}/runs/{runId}` 與 `best/{uid}` 規則已預留，但目前沒有寫入；第一版實際使用的是 `players/{uid}`（名稱）與 `summits/{uid}`（次數、最快時間）。

## ADR-10 3D 塔身與環繞攀爬（2026-11-13）

使用者決定：所有攀爬關卡改成 3D，以台北 101 主體為中心，鏡頭固定看著大樓、可 360° 旋轉；霍將軍可繞到其他面爬（決策卡選「四面環繞攀爬」）。

- **規則**：`levels.json` 新增 `tower.faces`（1 = 舊的單面外牆，4 = 四面環繞）。四面時每面仍是 `widths` 的欄數，往外走過該面最外欄就轉角到下一面，沒有邊線可掉；兩面的危險欄在轉角相接，所以轉角是 2×danger 欄寬的危險區，風險值累積到 100 照樣墜落（原因仍是「太靠邊了」）。強風把人往該面較近的邊推，也就是推向轉角。障礙物每 12 列「每面」各 `obstaclesPer12Rows` 個，且一定留有從起點到頂的安全路線。其餘規則（ADR-02～06）不變，墜落仍回 1F。
- **外觀**：塔身由程式產生的低多邊形網格（`climb/TowerShape.ts` 定輪廓、`scenes/Tower3D.ts` 繪製）：基座 1–26F 往上收窄、26F 圓形裝飾、27–90F 八節各自往外張開（每節 8 層）、91–101F 頂部、塔冠與尖塔。一列 0.2 單位高，攀爬格貼著斜面排列。全部用頂點色 + unlit 材質（`resources/materials/vertex-color.mtl`），不用即時光影與後製，目標中階手機 60fps。
- **鏡頭**：永遠看塔軸，跟著霍將軍的高度與所在面；玩家可拖曳畫面上半部、滑鼠拖曳或 Q／E 旋轉，放開 1.5 秒後轉回霍將軍那一面。HUD、天氣特效維持 2D 疊在上層。
- **外部模型**：Sketchfab 模型不可下載也無授權；3D Warehouse 模型貼圖為實拍照片（違反 ADR-08）。目前不採用，若日後取得授權清楚的模型，只作外觀層，攀爬格仍由程式產生。
- **試玩修訂（2026-11-13）**：每面兩側只留 1 欄危險區（轉角處兩面合計 2 欄；竹節外張的頂端 24 列仍各加 1 欄）。`levels.json` 每關加 `startPlatform`：第 1 關（廣場）、第 4–13 關（節與節之間的平台、屋頂）的第 0 列是平台，霍將軍站著走路、可繞塔，沒有危險區、風險不會上升、強風不會推人；往上攀到牆上才恢復規則，強風／老鷹／下雨照常作用。
- **尖塔**：第 13–14 關是爬梯（1 欄，不繞面，不能橫移），從塔冠頂往上，第 14 關頂端是塔尖平台。
- **結束動畫**：通過第 14 關後約 10 秒，霍將軍坐在塔尖平台邊緣面向城市，鏡頭先從肩後往下俯瞰，再拉遠繞塔尖；之後顯示攀爬時間，可點擊跳過（取代 ADR-07 的破關鏡頭）。
- **迷你地圖**：右上角顯示 101 剪影、目前關卡區段與霍將軍位置。

## ADR-11 台北盆地地景與大氣（2026-11-14）

使用者要求：101 四周要像從 101 看出去的台北盆地（綠色山脈環繞、密集城市平原、河流），並加入大氣系統（分層漸層天色、飄動的雲），手機網頁也要順。

- **地景**（`climb/BasinShape.ts` 定配置、`scenes/Basin3D.ts` 繪製）：一張極座標高度場同時畫城市平原與環山（每 2° 一段），北邊最高、西北留河口缺口，山腳距塔 540–810、最遠到 1600；塔東有一座小山。兩條河（東邊流入、繞過塔北，與西南來的大河匯流後從西北出海）、三座公園。城市約 1,200 棟街廓集中在盆地中央（距塔 460 內），靠塔密、往外漸疏漸矮，外圈到山腳是綠色田野（依使用者附的盆地參考圖），塔東北有高樓群，廣場周圍較矮以免擋住塔基；練習模式留一條看向遠方 101 的視線。山用飽和的綠色、最高峰頂偏土黃；距離越遠稍微偏霧色（空氣透視）。
- **大氣**（`scenes/Atmosphere3D.ts`）：跟著鏡頭的天空穹頂，依仰角分層漸層（地平線淡、頭頂深藍），越接近塔尖天色越深；下雨時轉灰陰天、雲變灰；強風時雲飄得更快。雲分低、中、高三層（110–420 高），各層以不同速度繞塔漂移，離塔軸至少 200，不會擋到鏡頭。
- **效能**：全部沿用頂點色 + unlit 材質，光影與霧色烘進頂點色；地景約 6 個 draw call、天空與雲 4 個；每幀只移動節點，天空只在顏色變化超過一階時重建（約 400 頂點）。每個網格低於 65,536 頂點。相機 far 改為 2,400 以涵蓋穹頂。
- **數值位置**：這些都是畫面比例，不是玩法數值，所以放在程式常數，不進 `levels.json`（同 ADR-10 的塔身比例）。
- **截圖**：`docs/screens/basin/`。

## ADR-12 雙語與全螢幕（2026-11-14）

使用者要求：主畫面可切換中文／英文，並能全螢幕遊玩（PR #24）。

- **決策**：所有玩家看得到的文字集中在 `core/I18n.ts`，`t('key', { var })`；`zh-TW` 為預設，另有 `en`。兩種語言的 key 與 `{佔位}` 必須一致（`tests/i18n.test.ts`）。選擇存在 `Settings.lang`，切換時重新載入 Home 場景（UI 全由程式建立，重載最不會漏）。`levels.json` 的關卡名稱維持中文，英文名在 `translateLevelName()` 對照，不讓數值檔多一份翻譯。
- **全螢幕**：`core/Fullscreen.ts` 用標準 Fullscreen API 加 WebKit 前綴。iPhone Safari 沒有元素全螢幕，按下時提示「分享 → 加入主畫面」；已從主畫面開啟（standalone）時提示已是全螢幕。
- **後果**：新增任何玩家文字都必須同時寫中英兩邊；Agents.md 的開發規則已註明。

## ADR-13 主畫面版面與黃昏 3D 背景（2026-11-14～15）

- **背景（PR #25）**：主畫面改用攀爬同一套 `Tower3D`、`Basin3D`、`Atmosphere3D`，傳入黃昏外觀（紫到桃色天空、玫瑰棕山、暗色城市燈光、亮窗、金色泛光、尖塔紅燈），視角從塔東象山看 101、鏡頭緩慢晃動。調色與鏡頭數學在純 TS `climb/BasinShape.ts`。3D 準備好前與失敗時改用 2D 的 `HomeBackdrop`。理由：同一份網格不需額外素材，也符合 ADR-08 原創要求。
- **版面（PR #27、#33）**：依使用者參考圖，左上 Logo＋標題、左側選單直欄（開始遊戲高亮，其餘選擇關卡／練習模式／登頂排行榜／設定，各有英文副標，底部周目與最佳紀錄）、右上語言／全螢幕膠囊＋帳號膠囊＋音量鈕；橫式上下黑條、直式只有底部；101 以 `homeYawShift` 站在選單右側。直式時帳號膠囊與音量鈕換到第二列。email 超過 26 字截斷（`core/TextClip.ts`）。
- **網頁不出捲軸**：`tools/site-icons.mjs` 的 `NO_SCROLL_STYLE` 在 `publish:site` 時插入 `index.html`。
- **數值位置**：版面尺寸是 UI 常數，放在 `Home.ts` 的具名常數，不進 `levels.json`。

## ADR-14 合成音效與 BGM（2026-11-13）

- **決策**：音效與 BGM 用 Web Audio 即時合成（`core/Audio.ts` 的 `SOUNDS`、`TRACKS`；`core/Sound.ts` 的 `sound()` 共用引擎），不使用任何音檔（PR #13）。
- **理由**：完全原創、無授權問題（ADR-08）；不增加下載量；音色可用程式微調。
- **規則**：跟著設定的音量（平方曲線）與靜音；瀏覽器要等第一次點擊或按鍵才出聲。Home 與 Climb 各一首五聲音階循環 BGM，暫停、墜落、登頂時停音樂。
- **取捨**：音色較簡單；日後若要換成錄製音檔，保留 `sound().play(id)` 介面即可。

## ADR-15 窗內 NPC（2026-11-13～14）

- **決策**（PR #14）：玻璃窗內放路人、員工、觀光客，攀爬者靠近時揮手或拍照，危險或墜落時擔心。配置在純 TS `climb/CrowdPlan.ts`，繪製在 `scenes/WindowCrowd.ts`（身體合成一個 mesh，只有手臂是節點）。
- **規則**：純裝飾，**不使用本局種子亂數**（用每關固定雜湊），所以開發規則 4 的「事件與機率用種子亂數」不受影響；只放在安全欄、整層無通風口的窗，門、雨遮、石柱後面與尖塔不放。
- **修訂（PR #22）**：第 9 關起塔變窄，只有 `cols / refCols` 比例的樓層放 NPC；通風口密度同步降低（`obstaclesPer12Rows` 可為小數）。參數在 `levels.json` 的 `crowd`。

## ADR-16 現實攀爬時間顯示（2026-11-15，2026-11-20 修訂倍率）

- **背景**：霍將軍實際爬 101 約 91 分鐘，遊戲約 10 分鐘就能登頂，玩家看到「10 分鐘」沒有真實感。
- **決策**（PR #34、#35）：顯示改為現實攀爬時間 = 遊戲時間 × `REAL_TIME_FACTOR`（`core/RealTime.ts`，**9.5**；最初 9，2026-11-20 改為 9.5）。`formatRealDuration()` 只顯示時＋分（分鐘無條件捨去）。用在關卡 HUD、墜落／練習完成／登頂結算（登頂另附原始遊戲時間）、主頁最佳紀錄、排行榜最快時間。
- **只改顯示**：本機紀錄、Firestore `bestRunMs`、排序、`firestore.rules` 都維持原始遊戲毫秒，所以改倍率不需要遷移資料或改規則。
- **數值位置**：倍率是呈現用常數，放在 `RealTime.ts`，不進 `levels.json`（不影響玩法）。

## ADR-17 版本號（2026-11-15）

- **決策**（PR #32）：`package.json` 的 `version` 是唯一來源（目前 1.0.0，SemVer）。Cocos 執行期讀不到 package.json，所以 `core/Version.ts` 的 `APP_VERSION` 鏡像同一個值，`tests/version.test.ts` 檢查兩者一致。設定頁「完成」鈕下方顯示「版本 v1.0.0」。
- **發版**：兩處一起改，合併後在合併提交打 `vX.Y.Z` tag 並建立 Release。
