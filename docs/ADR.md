# ADR：霍將軍爬101大樓

- 狀態：**已接受（Accepted）**，2026-11-13 審查完成
- 決策者：Tiger
- 線上版：https://claude.ai/artifact/DM75tsab18U1bXhtM2wpiT

## 背景與範圍

以 Cocos Creator 3.8 + TypeScript 製作 2D 垂直攀爬遊戲，共 14 關，從 1 樓爬到 101 塔尖，核心樂趣是「看懂風險、該停就停」。

靈感來源：國際攀岩好手 Alex Honnold（台灣暱稱「霍將軍」）以無繩索、無安全網的方式挑戰攀爬台北 101（[鏡週刊 2026-01-24 報導](https://www.mirrormedia.mg/story/amp/20260124edi031)）。

**範圍內**：開場、14 關垂直攀爬、關卡間上捲過場、破關環顧城市動畫；風險值系統（太靠邊、強風、下雨、老鷹）；墜落回 1 樓；尖塔段垂直爬梯（背景維持 101 原貌）。

**範圍外（第一版）**：射擊與戰鬥（「魂斗羅風格」只指像素美術、節奏與手感）、多人連線、付費機制、線上排行榜（第二版；Google 登入在第一版）。

## ADR-01 技術選型

**決策**：Cocos Creator 3.8 LTS + TypeScript。第一版輸出 Web Mobile / Web Desktop；Android、iOS 原生打包後期決定。關卡與風險參數放 `levels.json`，程式不寫死數值。

**理由**：同一專案可建置網頁與 Android / iOS；視覺編輯器適合風、雨粒子與光線特效；TypeScript；3.8 為官方 LTS（[Cocos 論壇](https://discuss.cocos2d-x.org/t/cocos-creator-3-8-2-lts-has-been-released/60245)）。

**引擎現況**：2026-01-05 Cocos 宣布 COCOS 4 以 MIT 授權全面開源，引擎與編輯器拆開，編輯器改為獨立 IDE「PinK」；COCOS 4 為 3.x 演進版並承諾向前相容。先用 3.8 LTS，原生打包階段再評估是否升級。

| 方案 | 優點 | 缺點 | 結論 |
| --- | --- | --- | --- |
| Cocos Creator 3.8 LTS | 穩定、編輯器完整、網頁與原生一次涵蓋 | 編輯器進入轉型期 | **採用** |
| COCOS 4 + PinK | MIT 開源、官方未來主線 | 編輯功能仍在遷移 | 觀察 |
| Phaser 3 + TS | 網頁輕量 | 原生 App 要另外包 | 不採用 |
| Godot 4 | 免費、原生輸出強 | 要學 GDScript | 不採用 |

**系統切分**：Scenes：Boot → Home → Intro → Climb → Transition → Fall → Victory；Practice。Components：InputController、RiskSystem、WeatherSystem、EagleSystem、WindowCrowd、LevelLoader、AuthService。事件用種子亂數。

**後果**：場景與 Prefab 為編輯器產生的 JSON，同一場景同時只一人改，邏輯寫在 TS 元件。

## ADR-02 核心操作與攀爬機制

**決策**：101 外牆正面視角，角色沿窗框格線上下左右移動；**放開所有方向鍵 = 靜止抓牢**，是闖過風、雨、老鷹的唯一方法。

**抓牢狀態**：放開方向鍵後角色四肢貼緊牆面、低頭；不另設按鈕。抓牢時不受風、雨影響，也不會被老鷹發現。

| 裝置 | 移動 | 靜止抓牢 |
| --- | --- | --- |
| 鍵盤 | 方向鍵 / WASD | 不按任何鍵 |
| 手機 | 左下虛擬搖桿 | 手指離開搖桿 |
| 手把 | 左類比 / 十字鍵 | 放開 |

- 每格 = 一塊窗格，一次爬一格，16-bit 像素動畫
- 水平五區：墜落線｜危險區｜安全區｜危險區｜墜落線
- 101 每節外牆外斜，進入新一節時安全區變窄
- 不提供跳躍、射擊

**關卡上捲**（參考 FC《Ice Climber》，只借用上捲過場）：抵達平台 → 鏡頭約 1.5 秒上捲 → 出現下一關樓層標示，無黑屏 → 繼續爬。不加敲磚、跳躍。

## ADR-03 風險值系統

| 風險值 | 狀態 | 角色表現 | 畫面與音效 |
| --- | --- | --- | --- |
| 0–39 | 安全 | 正常攀爬 | 風聲、城市音 |
| 40–69 | 緊張 | 發抖、冒汗、抱緊牆 | 心跳、邊緣淡紅 |
| 70–99 | 危機 | 單手懸掛、腳滑；操作輕微延遲 | 心跳加快、畫面微晃、紅框閃爍 |
| 100 | 墜落 | 失手後仰往下掉 | 尖叫 → 墜落場景 |

| 來源 | 條件 | 風險變化 |
| --- | --- | --- |
| 危險區 | 在左右邊緣區帶 | 每秒 +15 |
| 墜落線 | 踏出最外側窗格 | 直接 100 |
| 強風中移動 | 強風期間有方向輸入 | 每秒 +25，被向外推 |
| 下雨中移動 | 雨中移動超過 0.3 秒 | 直接 100 |
| 老鷹攻擊 | 被發現後仍移動 | 直接 100 |
| 回穩 | 安全區靜止抓牢 | 每秒 −20 |
| 回穩 | 安全區正常攀爬 | 每秒 −5 |

跨關不重置風險值。

## ADR-04 環境事件

| 事件 | 多久一次 | 預警（前 1 秒） | 持續 | 沒停下來的後果 |
| --- | --- | --- | --- | --- |
| 強風 | 每 60 秒判定，有機率發生（依關卡） | 左上「強風」圖示；雲加速、旗子傾斜 | 隨機 10–20 秒 | 風險每秒 +25，被推向外側 |
| 下雨 | 每 600 秒 | 左上「下雨」圖示；天轉暗、滾雷 | 隨機 20–30 秒 | 雨中移動超過 0.3 秒即墜落 |
| 老鷹 | 第 300 秒起每 600 秒 | 左上「老鷹」圖示；鷹嘯 | 固定 3 秒快速飛過 | 移動中被發現 → 俯衝 → 墜落 |

- 計時只算實際攀爬時間；墜落重來歸零
- 圖示事件期間保留並顯示剩餘時間條；三個圖示形狀可區分
- **同一時間只有一個危機事件**：到期事件排隊，前一個結束後至少 4 秒才觸發；強風判定撞到其他事件則跳過
- 老鷹：靜止 = 隱身（貼牆半透明）；移動中被發現有約 1.2 秒警告，停下即轉隱身

**環境動畫**：強風（風線、落葉）、老鷹（拍翅飛過、影子掃過玻璃）、烈日（純視覺，亮度與反光）、下雨（雨絲、水珠、閃電）、窗內群眾（NPC 拍照、揮手，純視覺；閃光低頻低亮，可關閉）。

## ADR-06 失敗與重來規則

任何一關墜落即本局結束，一律從 1F 第 1 關重來，無中繼點、無命數。墜落流程：凍結 0.3 秒 → 墜落動畫（不呈現撞擊）→ 結算（最高樓層、墜落原因、歷史最佳）→ 再爬一次。

練習模式：主畫面「開始遊戲」與「練習模式」；練習 = 三層樓平房，風、雨、老鷹各低強度示範一次，約 1 分鐘，不計紀錄。

## ADR-07 開場與破關場景

開場：原創插畫（紅衣角色 + 101 天際線）放大 3 秒 → 主畫面（Google 登入、開始遊戲、練習模式）→ 鏡頭拉近 101 底部 → 第 1 關。
破關（約 15 秒）：觸及塔尖 → 音樂高昂 → 環顧城市 → 360° 台北市景 → 揮手、總時間、墜落次數。

## ADR-08 素材、肖像與商標風險

素材全面原創；角色無品牌 Logo、臉不仿真人。公開版名稱沿用「霍將軍爬101大樓」，未登入時角色預設名「霍將軍」。
殘留風險：「霍將軍」為真人暱稱，可能被理解為代言或授權；「TAIPEI 101」為註冊商標。上架商店前請法務確認，必要時只換名稱。（設計風險提示，非法律意見）

## ADR-09 Google 登入與玩家名稱

| 狀態 | 角色名稱 | 紀錄 |
| --- | --- | --- |
| 未登入 | 「霍將軍」 | 本機 localStorage |
| 已登入未改名 | Google 顯示名稱 | 雲端 |
| 已登入已改名 | 玩家設定（1–12 字，過濾不雅字） | 雲端 |

實作：**Firebase Authentication + Firestore（採用）**；自建 Java API 不採用（保留日後串接）。只存 uid、名稱、紀錄，不存 Email；需隱私權聲明。

**部署 GitHub Pages**：
1. Firebase 授權網域加入 `<帳號>.github.io`
2. Google 登入一律 `signInWithPopup`（redirect 在封鎖第三方儲存的瀏覽器會失效，[Firebase 文件](https://firebase.google.com/docs/auth/web/redirect-best-practices?hl=zh-TW)）
3. 彈窗必須由玩家點按鈕觸發
4. Firebase 設定可進公開 repo；服務帳戶金鑰絕不 commit；安全靠 Firestore 規則
5. GitHub Actions 發布 Pages

**第二版排行榜**：沿用 Firestore；登入者每人一筆最佳紀錄，依樓層高→低、時間短→長取前 50（複合索引）；第一層防作弊用安全規則擋不合理數字；伺服器驗證需 Cloud Functions（Blaze 方案）。備選 Supabase（可接 Firebase 登入，[文件](https://supabase.com/docs/guides/auth/third-party/firebase-auth)；免費專案一週低活動會暫停）。

## ADR-10 3D 塔身與環繞攀爬（2026-11-13）

使用者決定：所有攀爬關卡改成 3D，以台北 101 主體為中心，鏡頭固定看著大樓、可 360° 旋轉；霍將軍可繞到其他面爬（決策卡選「四面環繞攀爬」）。

- **規則**：`levels.json` 新增 `tower.faces`（1 = 舊的單面外牆，4 = 四面環繞）。四面時每面仍是 `widths` 的欄數，往外走過該面最外欄就轉角到下一面，沒有邊線可掉；兩面的危險欄在轉角相接，所以轉角是 2×danger 欄寬的危險區，風險值累積到 100 照樣墜落（原因仍是「太靠邊了」）。強風把人往該面較近的邊推，也就是推向轉角。障礙物每 12 列「每面」各 `obstaclesPer12Rows` 個，且一定留有從起點到頂的安全路線。其餘規則（ADR-02～06）不變，墜落仍回 1F。
- **外觀**：塔身由程式產生的低多邊形網格（`climb/TowerShape.ts` 定輪廓、`scenes/Tower3D.ts` 繪製）：基座 1–26F 往上收窄、26F 圓形裝飾、27–90F 八節各自往外張開（每節 8 層）、91–101F 頂部、塔冠與尖塔。一列 0.2 單位高，攀爬格貼著斜面排列。全部用頂點色 + unlit 材質（`resources/materials/vertex-color.mtl`），不用即時光影與後製，目標中階手機 60fps。
- **鏡頭**：永遠看塔軸，跟著霍將軍的高度與所在面；玩家可拖曳畫面上半部、滑鼠拖曳或 Q／E 旋轉，放開 1.5 秒後轉回霍將軍那一面。HUD、天氣特效維持 2D 疊在上層。
- **外部模型**：Sketchfab 模型不可下載也無授權；3D Warehouse 模型貼圖為實拍照片（違反 ADR-08）。目前不採用，若日後取得授權清楚的模型，只作外觀層，攀爬格仍由程式產生。
- **待辦**：第 13–14 關尖塔段；登頂後約 10 秒結束動畫（霍將軍坐在塔頂邊緣俯瞰城市，取代 ADR-07 破關動畫的鏡頭）。
